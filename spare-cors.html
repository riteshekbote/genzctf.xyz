api.sparelabs.com — reflected-Origin CORS with credentials

Target: https://api.sparelabs.com/v1 · Class: ApiMisconfig CORS · Server reflects ANY Origin + allow-credentials:true + allow-headers:Authorization (no allowlist).

1. Proof in browser context (this page, hosted on attacker origin genzctf.xyz)

This page performs a cross-origin fetch(..., {credentials:"include"}) against the target API. With a functional CORS policy these calls must fail (no Access-Control-Allow-Origin for this origin). With the buggy policy they succeed and the server's data is readable from any website.

idle.

2. Preflight/GET header capture (server responses)

OPTIONS /v1/journeys/requests   Origin: https://genzctf.xyz
Access-Control-Allow-Origin:  https://genzctf.xyz   (reflected, any)
Access-Control-Allow-Credentials: true
Access-Control-Allow-Methods: GET,HEAD,PUT,PATCH,POST,DELETE
Access-Control-Allow-Headers: Authorization

GET /v1/global/organizations    (no Authorization header at all)
200  Access-Control-Allow-Origin:  ; Access-Control-Allow-Credentials: true

3. Reproduce (server-side truth, passive)

curl -i -X OPTIONS "https://api.sparelabs.com/v1/journeys/requests" \
  -H "Origin: https://genzctf.xyz" -H "Access-Control-Request-Method: POST" \
  -H "Access-Control-Request-Headers: Authorization"
curl -i "https://api.sparelabs.com/v1/global/organizations" -H "Origin: https://genzctf.xyz"
curl -i "https://api.sparelabs.com/v1/global/regions" -H "Authorization: Bearer x" -H "Origin: https://genzctf.xyz"

Scope note (honesty): data readable cross-origin is platform bootstrap/config; auth is Bearer (SPA) so a victim's authenticated session is not transmitted by the browser today. This finding is a standing misconfiguration: any Origin can perform credentialed reads of every open /v1 route and future cookie-based endpoints are automatically exposed. Recommended fix: replace reflective ACAO with an explicit allowlist and stop emitting allow-credentials:true together with reflection.
